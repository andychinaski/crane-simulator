# ARCHITECTURE — инженерный план

## 1. Стек и границы

- **Vite + Vue 3 + TypeScript**: разметка, реактивные слайдеры, статус, кнопки.
- **Three.js (WebGLRenderer)**: 3D-сцена, материалы, освещение, меши, scene graph. `OrbitControls` — базовый механизм взаимодействия с камерой.
- **Vitest**: тесты логики/кинематики без WebGL. **Playwright**: пользовательские сценарии и скриншоты, если среда умеет запускать WebGL.
- Сборка статическая, без бэкенда. Допускается локальный запуск и публикация через обычный static hosting. Установленные зависимости фиксировать lock-файлом.

Выбор сделан для компактной контрольной; **не вводить** физический движок, Pinia/глобальную state-машину библиотекой, тяжёлый UI-kit или backend просто потому, что «так принято».

## 3. Координаты и иерархия

**Единицы:** метры, углы в UI — градусы, во внутренней Three.js математике — радианы. **Y — вверх**, X/Z — плоскость пола, y=0 — уровень пола. Изначальная стрела направлена по локальной +X; поворот платформы вокруг Y.

```text
worldScene
├─ floor + grid + deliveryZone
├─ craneBase               (НЕ вращается)
│  └─ slewingPlatform       (yaw вокруг Y)
│     ├─ housing / railings / machinery
│     └─ boomPivot          (pitch вокруг локальной Z)
│        ├─ mainBoom
│        ├─ telescopicStages (вдвигаются вдоль локальной X)
│        ├─ hydraulicPiston (согласован с pitch)
│        └─ boomTip / pulley [anchor для расчётов]
├─ hangingAssembly          (положение в WORLD, не наследует pitch)
│  ├─ verticalRope          (между tip и точкой подвеса)
│  └─ gripperRoot           (yaw вокруг WORLD Y)
│     └─ symmetricClaws     (open/close)
├─ cargoCrate               (отдельно на полу ИЛИ сцеплен с захватом)
└─ camera + orbitControls
```

Критический инвариант: при любой ориентации стрелы вычислять **мировую** позицию шкива через world matrix, ставить подвес под ним, а **трос держать вертикальным**. Привязывать весь захват дочерним узлом наклоняемой стрелы без компенсации запрещено.

Длина стрелы — смещение вложенных телескопических секций/положения tip, **не глобальное масштабирование**. Гидроцилиндр должен визуально соединять две корректные точки и удлиняться/ориентироваться при наклоне.

## 4. Состояние и кадр

Источник управляющих параметров: `config/controls.json`. Для каждого механизма есть `target` и `actual` (реализованное положение). Применяй ограничения и плавно двигай `actual` к `target` с максимально допустимой скоростью `rate * speedFactor * deltaTime`; не используй FPS-зависимый шаг. Ограничь длинный `deltaTime` после ухода вкладки в фон. Мгновенный snap допустим только при **явном reset сценария**, а не при обычном движении.

Один кадр:
1. Обновить target (пользователь или DemoSequence), действительные ограничения и скорости.
2. Продвинуть actual регуляторов в пределах dt и допустимых комбинаций.
3. Обновить scene graph крана и world matrices.
4. Вычислить tip, вертикальную геометрию троса, положение и ориентацию захвата.
5. Обновить связь груз/захват и геометрию ящика, проверить пол/площадку.
6. Синхронизировать отображение статуса и UI; обновить controls камеры, отрисовать.

Состояния груза: `GROUND`, `ATTACHED`, `PLACED` (или эквивалентные); переходы должны иметь чёткие предикаты, не зависеть от случайных событий рендера. Для прикрепления сохранять допустимое взаимное положение handle/gripper; если перепривязываешь `Object3D`, сохраняй мировое положение. Не дублировать мировые координаты ящика в двух разных подсистемах.

## 5. Захват и достижимость

Проверь достижимость **и первоначального ящика, и площадки** диапазонами поворота/наклона/телескопирования/троса. Можно подобрать реальные мировые координаты объектов **до G1**, после G1 их изменение — только если выявлена геометрическая проблема, с сообщением владельцу.

Привязка: когда раскрытие снижается до рабочего порога, допускается захват только при близости `gripperAnchor` к `crateHandleAnchor` и согласованном yaw. Пороги разработчик выбирает так, чтобы это было удобно человеку; фиксирует в тестах. Если захват не состоялся — явная подсказка. Освобождение — рядом с полом, ящик остаётся на текущем X/Z; верхняя ручка должна быть визуально там, где зацепился захват. Груз может опуститься только до касания пола, не сквозь него.

**Не требуется:** динамика маятника, разрывы троса, точная механика гидравлики, rigid body physics. Требуется кинематически достоверное движение и понятные ограничения.

## 6. Камера без разрушения мира

`OrbitControls` управляет азимутом, наклоном и масштабом камеры. «Горизонталь» и «Вертикаль» смещают центр ортографической проекции вдоль осей кадра и сохраняют центр обхода в сцене. Панорамирование мышью переводится в те же смещения. Колесо меняет общий с ползунком масштаб проекции. «Сбросить вид» восстанавливает стартовые смещение, масштаб и углы камеры, сохраняя положение крана и ящика.

## 7. Демонстрация

Сценарий как явный конечный автомат: `RESET → APPROACH → ALIGN → CLOSE → VERIFY_ATTACH → LIFT → SWING → LOWER → OPEN → VERIFY_DELIVERY → COMPLETE` (названия необязательны). Переходы — по фактическому достижению положений/условий, **не только по таймеру**. Те же limits и кинематика, что при ручном режиме. `STOP` отменяет дальнейшие команды автомата и убирает скорость автодвижения (без сброса фактической позы); ручной режим снова доступен. Скорость из слайдера применяется к движениям демонстрации.

## 8. Проверки, производительность, ресурсы

- Референс: снимки реального приложения в 1672×941, 1440×900 и 1280×720; сравнить с `assets/reference/crane-ui-reference.png` по структуре, цветам, силуэту и размерам, **не pixel-perfect diff**.
- Desktop Firefox/Chrome или Chromium с WebGL; WebGL unavailable → дружелюбная ошибка, а не пустой canvas.
- При resize корректный aspect/canvas, пиксельная плотность ограничена (например DPR ≤2), dispose геометрий/материалов/listeners на unmount.
- Критические инварианты тестируются без браузера; сценарии управляются через UI в E2E, если доступен браузер с WebGL.

Справка по официальным API: https://threejs.org/docs/pages/OrbitControls.html , https://threejs.org/manual/pages/scenegraph.html , https://vite.dev/guide/ .

## 9. G5 — презентационный слой обучения

Обучение — только Vue/DOM поверх существующего интерфейса. В текущем `src/App.vue` целевые зоны имеют классы `.viewport`, `.camera-panel` и `.crane-panel`. Возможен отдельный `src/components/OnboardingTour.vue`, без глобального store, роутера, нового canvas и нового Three.js render loop.

Позиционирование spotlight привязать к реальным DOM-границам и адаптировать к resize; существующие компоненты не переносить/клонировать. В активном туре блокировать управление underlying UI/OrbitControls, а после закрытия гарантированно восстанавливать. Не менять механику крана и демонстрации. Подробности в `docs/G5_ONBOARDING.md`.

## G7 — UI-only extension boundaries

Use existing Vue UI for overlays and tour/guided cards, and existing camera controller for proper baseline recalibration. Global dim remains page-wide; dialog positions are computed relative to 3D-scene layout. Tour tooltip placement reacts to resize/scroll and spotlight bounds. Guided visual state derives from G6 actual/verified state, not DOM input targets; preserve G6 route/contextual invariants. Scenario reset ≠ camera reset ≠ stop demo. Avoid additional dependencies and Three.js model changes. Detailed contract: `docs/G7_UI_POLISH.md`.

Порог раскрытия из `config/g6-route.json` применяется и на шаге отпускания, и при проверке сохранённых условий. Шаг подъёма груза использует фактический отрыв ящика от пола. Simulator запоминает высоту захвата при отпускании ящика на площадке, чтобы проверять подъём пустого захвата по разнице высот.
