# QA — проверка вместо «вроде работает»

## Принцип

`build PASSED` ≠ «симулятор работает». Любой этап считается технически выполненным только после применимых **тестов, живого запуска, проверки требований**. Ключевые визуальные и поведенческие рубежи принимает только пользователь. **Запрещено** выдавать мокап/референс за скриншот реализации.

## Минимальные npm-команды после S00

- `npm run dev` — локальная работа приложения.
- `npm run typecheck` — TS-диагностика.
- `npm run test` — Vitest, проверки логики/геометрии/сценария.
- `npm run build` — production сборка.
- `npm run check` — последовательно typecheck + test + build; код возврата ненулевой при любой ошибке.
- `npm run test:e2e` — Playwright, когда возможно запустить браузер с WebGL; браузерная проверка может быть неработоспособна в headless-контейнере: это **ограничение проверки**, а не «зелёный тест».

Если не удаётся получить скриншоты из браузера, агент объясняет ограничение и даёт пользователю локальный маршрут приёмки. Каждый раз отдельно сообщать что **фактически** запускалось и завершилось.

## Инварианты для обязательных unit-тестов

1. Диапазоны `config/controls.json` валидны; значения по умолчанию внутри них; **все 11** полей присутствуют; названия и единицы не подменяются.
2. Кинематика не порождает `NaN`, бесконечности, резких сдвигов на обычном `dt`; изменения на 30/60/120 FPS дают сопоставимую финальную позу при одинаковом симулированном времени.
3. Поворот платформы не меняет координаты неподвижного основания; наклон меняет высоту boomTip; выдвижение меняет вылет boomTip; **ropeEnd.xz == boomTip.xz** в пределах допуска.
4. Наклон/поворот не наклоняют захват от вертикали; длина троса влияет на вертикальное положение; концы троса соединены с шкивом/подвесом.
5. Низ захвата и ящика не проникает под пол; некорректные предельные сочетания ограничиваются явно.
6. Открытый захват не несёт груз; закрытие вдали от ручки не прикрепляет; корректный захват прикрепляет; сцепленный ящик повторяет движение крюка/захвата.
7. Освобождение в допустимой низкой позиции сохраняет X/Z и ставит ящик на пол; высокое освобождение блокируется с явным статусом.
8. При полном цикле Демо груз оказывается внутри зоны, отделён от захвата; `STOP` не телепортирует и сохраняет позу в момент остановки.
9. Сброс камеры не меняет параметры крана и состояние груза.

## Контрольные точки (обязательно остановиться)

### G1 — визуальная основа

До этого рубежа агент реализует реальную WebGL-сцену и **узнаваемую, достаточно детализированную** неподвижную модель крана; UI содержит все элементы/числовые подписи, но часть регуляторов пока может быть заглушками с понятной пометкой *«в работе»*. Никаких ложных эффектов.

**Доказательства:** `evidence/G1/main-1672x941.png`, `main-1440x900.png`, `main-1280x720.png`; перечень принципиальных отклонений от референса; рабочая ссылка на локальный запуск. Важное: скриншот **выполненной сцены**.

**Владелец смотрит:** кран действительно жёлтый и узнаваем как референс; видны секции стрелы, кабина/корпус, гидравлика, основание, шкив, трос, захват; ящик и зона; панели стоят там, где ожидается; размер объекта на сцене адекватен. **Не переходить к анимациям до принятия.**

### G2 — управляемый механизм

Все 7 ползунков привязаны к настоящей кинематике, камера управляется 4 нижними ползунками и мышью. Горизонтальное и вертикальное смещения следуют осям кадра при любом азимуте. Масштаб регулируется ползунком и колесом. Нет разрывов в узлах, трос строго вертикальный, движения плавные, `speed` изменяет время движения. Поведение при недопустимых ограничениях понятно.

**Доказательства:** тесты; краткое видео (если доступно) или серия реальных скриншотов на разных положениях; инструкция владельцу «передвинь эти 3 регулятора — увидишь то-то».

**Владелец смотрит:** двигается нужная деталь, направление правильно, прочие части не ломаются; камера не поворачивает реальный мир; сброс вида не сбрасывает кран. **Остановка до G2 принято.**

### G3 — захват/перенос/укладка

Ручной сценарий **с начального положения**: открыть захват → совместить с ручкой → закрыть → поднять ящик → переместить к зоне → опустить → раскрыть → груз остаётся на площадке. Траектория реально достижима. Есть понятная обратная связь при ошибочном захвате/слишком высоком освобождении.

Шкала троса остаётся от 0,5 до 8 м. При перетаскивании бегунок останавливается внутри шкалы на пределе текущей позы, даже если указатель движется дальше. При достижении пола число в панели соответствует пределу. При уменьшении предела бегунок смещается к новому допустимому положению. После освобождения ящика доступный ход бегунка увеличивается, трос сохраняет длину.

Пустой захват останавливается на крышке над ящиком и у пола рядом с ним. Попытка войти через боковую стенку блокируется с подсказкой. Сцепление с ручкой остаётся доступным.

**Доказательства:** тесты автомата сцепления; точные шаги для ручной проверки; фото «до», «в воздухе», «на площадке». **Остановка до G3 принято.**

### G4 — демонстрация и выпуск

Демонстрация проходит полный цикл без ручной помощи; «Стоп» останавливает, не сбрасывая модель, позволяя управление вручную; все панели реагируют, справка и сообщения работают; нет критических console errors; production build запускается; desktop адаптация приемлема.

Во время демонстрации бегунки плавно следуют за механизмами. Между действиями сохраняется неподвижная поза на 0,5 с и в панели указан результат шага. «Стоп» также отменяет следующий шаг во время паузы.

**Доказательства:** отчёт о проверках и реальный финальный скриншот; команда запуска; список известных ограничений, если остались. **Только после G4 принято можно утверждать «Готово».**

## Формат передачи на приёмку

```text
Gx — ожидает приёмки
Реализовано: ...
Проверено: typecheck ✅, unit ✅, build ✅, браузер ✅/НЕ ПРОВЕРЕНО
Открыть: npm run dev → http://localhost:5173 (или фактический адрес)
Скриншоты: evidence/Gx/...
Проверь: 1)... 2)... 3)...
Ограничения: ...
Ответь «Gx принято» или укажи правки.
```

При замечаниях возврат к реализации **того же этапа**, повторные тесты, новый скриншот и новый запрос приёмки. Фиксируй одобрение в `.agent/STATE.md` только после слов пользователя.
