# G5 — Вводное интерактивное обучение

Статус требования: **APPROVED FOR IMPLEMENTATION** (идея пользователя). Статус приёмки: **PENDING** до явного «G5 принято».

## Цель

При первом открытии веб-симулятора показать пользователю затемнение приложения и выбор из двух действий: **«Пройти обучение»** / **«Пропустить обучение»**. При выборе обучения провести короткий визуальный тур по уже существующему интерфейсу с подсветкой трёх реальных областей. При пропуске немедленно открыть обычный симулятор без изменений его состояния.

**G5 — исключительно UI/UX-расширение уже принятой версии G1–G4.** Архитектуру кинематики, Three.js, поведение управления краном, грузом, демонстрацией, камерами, цвета и размещение панелей не переделывать.

## Пользовательский сценарий

### Стартовый экран

- При **первом посещении** приложения поверх *всего интерфейса* (не только WebGL-canvas) появляется тёмный полупрозрачный overlay. Разметка, модель, сцена и существующие панели остаются видны под затемнением.
- В центре — компактная карточка «Добро пожаловать в симулятор крана», краткая фраза «Узнайте, как управлять сценой и механизмами» и **ровно два основных действия**: `Пройти обучение` и `Пропустить обучение`.
- Кнопка «Пропустить обучение» закрывает слой; не меняет положение крана, состояние груза, положение камеры, значения регуляторов и режим демонстрации. После закрытия всё работает как до G5.
- Кнопка «Пройти обучение» открывает первый шаг тура без навигации на другой маршрут и без перезагрузки страницы.
- Затемнение плавно появляется/исчезает; при `prefers-reduced-motion: reduce` анимации минимальны или отключены.

### Шаги тура — ровно три зоны

Порядок: **1. Камера → 2. Рабочая область → 3. Управление краном**. В каждый момент только одна зона визуально выделена — ярче остального интерфейса, с отчётливой контурной подсветкой и коротким пояснением. Модель/полотно не клонировать и не перемещать в DOM.

| Шаг | Существующий UI-элемент | Заголовок подсказки | Текст |
|---|---|---|---|
| 1 | `.camera-panel` | «Управление камерой» | «Регуляторы снизу изменяют вид: горизонталь, вертикаль, масштаб и обход сцены. Кнопка „Сбросить вид“ возвращает исходный ракурс.» |
| 2 | `.viewport` (3D-сцена) | «Рабочая область» | «Здесь находится трёхмерная сцена: кран, ящик и площадка доставки. Сцену можно рассматривать с разных сторон.» |
| 3 | `.crane-panel` | «Управление краном» | «Справа находятся семь регуляторов механизмов крана. Здесь же можно запустить демонстрацию и остановить её.» |

Для шага показывать `1 из 3` / `2 из 3` / `3 из 3`, заголовок, текст, кнопки `Назад` (кроме первого шага), `Далее` (на первых двух), `Завершить` (на последнем) и `Пропустить` (на всех шагах). Управление клавиатурой и хорошо видимый фокус обязательны. Подсказку размещать рядом с выделенной областью, **не перекрывая целевой участок**, насколько позволяет экран; при нехватке места — безопасное компактное положение в видимой части окна. Сцену и регуляторы при обучении **показываем, но не заставляем ими пользоваться**.

### Завершение и повторный запуск

- `Завершить` и `Пропустить` полностью снимают overlay, подсветку и блокировку ввода; не сбрасывают состояние симулятора.
- **Выбранный рабочий default для G5:** автоматически предлагать обучение только до первого пропуска/прохождения; сохранять признак в `localStorage` (без сервера и аккаунта). Если хранилище недоступно, интерфейс не падает и сессия работает.
- Добавить в существующую «Справку» действие `Пройти обучение ещё раз` (или равнозначное). Повторный запуск не обнуляет настройки камеры, позу крана и состояние груза. Существующий текст справки сохранить.
- Если пользователь закрывает тур через `Escape`, считать это пропуском; решение не теряется после перезагрузки, если localStorage доступен.
- При первом заходе на страницу с явным E2E/debug query-параметром, который нужен уже действующим тестам G4, не ломать сценарии тестов: агент должен либо изолировать onboarding в тестовой фикстуре, либо сделать существующие тесты явно пропускающими его. Не менять поведение работы демонстрации ради тестов.

## Визуальные требования

- Не менять текущую композицию, ширины/места существующих панелей, оригинальный тёмный стиль, цвета крана/захвата, количество и имена регуляторов.
- Overlay: аккуратное, достаточно плотное затемнение всего приложения. Spotlight: не просто рамка на тёмной секции — **выделенная область заметно светлее фона**, граница легко различима. Текст подсказки контрастный. Акцент разрешён текущий UI-оранжевый.
- На размерах 1672×941, 1440×900, 1280×720 не допускается исчезновение или обрезка подсказки, кнопок, прогресса. При изменении размеров окна активная подсветка привязана к реальным координатам соответствующей зоны.
- Не создавать второй Canvas, изображение или мокап вместо Three.js-сцены; не прерывать текущий render loop и не пересоздавать WebGL по шагам обучения.
- Пока overlay открыт, клики, скролл и drag по сцене/ползункам **не должны управлять краном и камерой**. Overlay не должен блокировать собственные кнопки навигации; после закрытия управление полностью возвращается.

## Технические ориентиры, а не обязанность копировать имена

- В текущем `src/App.vue` уже существуют `.viewport`, `.camera-panel`, `.crane-panel`, `<dialog>` справки и связка с `mountScene`.
- Предпочтительно отдельный Vue-компонент `src/components/OnboardingTour.vue` + компактная логика состояния (состояния `welcome`, `scene`, `camera`, `crane`, `closed`); небольшая интеграция в `App.vue` и CSS. Без новой зависимости, роутера, store или бэкенда.
- Реализовать spotlight в DOM/CSS поверх существующего экрана. Можно применять `getBoundingClientRect()` + `ResizeObserver`/`resize`, но обработчики очищать при unmount. Не перемещать `viewport`/WebGL canvas и не дублировать DOM.
- Сделать слои и фокус предсказуемыми: декоративная подсветка не должна ловить клики, интерактивны только кнопки тура. При закрытии/переходе возвращать фокус корректно. Существующий `<dialog>` справки не должен конфликтовать с onboarding.
- Текст карточек на русском. У полей должны быть удобные стабильные селекторы `data-testid` для E2E; DOM-классы существующих секций не переименовывать без необходимости.
- Повторный старт через «Справку» может быть доступен и после пропуска; не превращать его в новую отдельную страницу.

## Явно вне G5

- Изменения механики крана/ящика, полноценные интерактивные задания внутри обучения, голос/озвучка, дополнительные сцены, система уровней, регистрация/бэкенд, телеметрия, новая тема интерфейса.

## Приёмка G5 (человеком)

1. На чистом профиле при загрузке вижу затемнённый существующий симулятор и ровно два главных выбора.
2. `Пропустить обучение` сразу открывает исходный рабочий экран без видимых последствий.
3. `Пройти обучение`: по очереди реально подсвечиваются **сцена**, **нижняя панель камеры**, **правая панель крана**; текст соответствует зоне, интерфейс выглядит аккуратно.
4. `Назад`, `Далее`, `Завершить`, `Пропустить`, `Escape` работают ожидаемо; при турах не двигается кран/камера от случайных действий под overlay.
5. После закрытия прежние ручное управление, камера, демонстрация/Стоп, справка и перенос ящика работают; повторное обучение доступно из «Справки».
6. Перезагрузка не запускает тур повторно после первого выбора (если хранилище доступно). На узких desktop-разрешениях ничего не обрезано.
7. Агент приносит **реальные** снимки `evidence/G5/` (welcome + каждый spotlight), результаты `npm run check` и `npm run test:e2e`; при недоступной браузерной проверке честно указывает ограничение.
