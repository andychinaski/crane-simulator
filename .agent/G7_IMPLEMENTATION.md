# G7 — исполнительный план (не менять G6 механику)

Источник: `docs/G7_UI_POLISH.md` + изображения `assets/reference/g7/`.

## Перед стартом

- Проверить, что ветка содержит **реально реализованный G6**. Если только G4/G5, STOP и запросить корректную ветку. Не восполнять за пользователя неизвестные изменения.
- Зафиксировать HEAD, `git status` и текущие скриншоты G5 welcome / G6 mode selector / G6 guided / базового кадра. Не выполнять разрушительных команд Git.
- Определить реальные компоненты: модалки G5/G6, тур/spotlight tooltip, scene toolbar, status, guided UI, CameraController и camera UI. Не полагаться на имена из старых архитектурных планов; читать актуальный код.

Разрешено самостоятельно сгруппировать кодовые изменения для минимизации диффа, но **не пропускать проверки**. Оставить архитектуру G1–G6. Не менять маршрут из `config/g6-route.json`, `DemoSequence`, `CargoController` или `CraneMotion` без доказанной необходимости исправить регрессию и явного обоснования.

## Риски

- Наивный `position: fixed; left:50%` центрирует модалку по странице, а не по сцене. Нужен якорь/геометрия контейнера сцены.
- Наивное `width: 500px` у tooltip обрежет его на мобильном экране или закроет spotlight. Нужен `max-width` и fallback placement.
- Не перепутать остановку demo и полный reset. Cancel не должен терять pose и cargo.
- Два reset (сценарий/вид камеры) независимы.
- Guided success нельзя считать по одному значению HTML input; использовать фактическое состояние привода/груза из G6.
- Рисовать золотой check или оранжевый error **без сохранённого факта о предыдущем success** недостаточно: нельзя подсвечивать оранжевым во время первой попытки.
- Не превращать улучшение UX в новый layout/большой рефакторинг/новые зависимости.
- `STATE.md` может отставать от фактического Git: не утверждать, что G6 принят, если этого нет в документации/решениях владельца.

## Evidence / приёмка

Дать пользователю:
- снимок welcome и mode selection с центром сцены;
- снимки G5 tooltip у нижней панели и у сцены;
- confirm reset и последующий mode selection;
- четыре состояния green-active / green-success / orange-regressed / green-restored;
- фото (screenshot) откалиброванной камеры при `0/0/100%/0°`;
- результат тестов; список изменений и способ воспроизвести их вручную.

В конце: `.agent/TASKS.md` и `.agent/STATE.md` = G7 `AWAITING_APPROVAL`, не `DONE`. В отчёте 5–8 строк + 4–6 ручных шагов. Ждать «G7 принято».
