# G5 — маршрут реализации для coding-агента

Источник требований: `docs/G5_ONBOARDING.md`. Этот файл не заменяет канонический `.agent/TASKS.md`: `tools/apply-g5.mjs` зарегистрирует этап S05 и рубеж G5 в общей таблице.

## Текущий контекст

- G1–G4 приняты; реализация уже существует. **Не выполнять S00–S04 повторно**.
- Работа над G5 разрешена; перед началом проверь рабочую ветку и `git status`. Не стирай незакоммиченные изменения, не выполняй push без прямого указания.
- Существующие элементы: `src/App.vue` → `.viewport`, `.camera-panel`, `.crane-panel`, `<dialog>` «Справка»; CSS — посмотри текущие импорты и стили. Не полагайся на старую структуру из архитектурного плана, читай фактический код.

## Автономные подэтапы

1. **База:** проверить текущие селекторы и CSS, существующие тесты, сценарии G4 и доступные команды. Зафиксировать исходное состояние, без рефакторинга механики.
2. **Карточка входа:** full-screen затемнение, две кнопки, доступность, момент показа (first visit).
3. **Тур:** 3 выделяемые области, навигация и прогресс, корректное положение карточек при resize/разных высотах окна, блокирование управления под overlay.
4. **Возврат:** `Справка → Пройти обучение ещё раз`, завершение и пропуск, localStorage с безопасным fallback.
5. **Проверка:** unit для переходов/сохранения при целесообразности; Playwright для сценариев G5; `npm run check`; `npm run test:e2e`; живой браузер и снимки 3 размеров.
6. **Предъявление:** обновить `.agent/TASKS.md`, `.agent/STATE.md`, `.agent/DECISIONS.md` если приняты новые существенные решения; оставить `AWAITING_APPROVAL`, остановиться и показать владельцу.

## Инварианты

- G5 — отдельный слой интерфейса; никакие изменения в CraneMotion, CraneRig, CargoController, DemoSequence, CameraController или геометрии, если это не требуется обоснованной критической совместимостью.
- Не трогать `config/controls.json`, механические пределы, кинематику, существующие цвета/графику и исходный визуальный референс.
- Не объявлять «готово» по одной сборке, не подменять снимки мокапами.
- При конфликте поведения с открытым `<dialog>` «Справка» обеспечить однозначный переход, не два активных модальных слоя.

## Обязательные E2E-кейсы

- `fresh-storage` → welcome с двумя кнопками; под ним реальные 3 секции.
- `skip` → overlay исчез, управление рабочее; reload → welcome нет.
- `take-tour` → нижняя панель камеры → 3D-сцена → правая панель крана; back/next/final → overlay исчез.
- `restart-from-help` → существующая справка открывается, её текст сохранён, повторный старт работает после skip и после finish.
- `blocking` → drag/scroll/inputs под overlay не меняют значения/положение (или эквивалентная проверка); после закрытия возвращается работоспособность.
- `responsive` → welcome и подсказки целиком видны в 1672×941, 1440×900, 1280×720; spotlight привязан к зоне после resize.
- `regression` → G1–G4 сценарии не сломались; тесты G4 изолированы от first-visit onboarding без изменения поведения симулятора.
